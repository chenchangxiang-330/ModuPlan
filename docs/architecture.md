# 数据与规则

- `lib/data/models.dart`：本地日期键、模块边界、事项与备份字段验证。
- `lib/data/store.dart`：SQLite 仓储，所有修改通过事务进行，通知界面重读同一份数据。
- `lib/ui/`：四个页面、模板编辑器、底部事项表单。系统文件读写由 Kotlin MethodChannel 完成。

## 日期生命周期

`days.day` 是主键；存在即表示该日期已建立。普通查看不插入记录。首次手动保存或应用周模板时，复制三个默认模块的名称、时间和颜色到日期快照。删除最后一条事项也不删除日期记录。应用空白模板仍建立日期。只对不早于今天且未建立的日期生成事项，事务将重复点击串行化。

每条 `entries` 事项使用随机稳定 ID；编辑和移动保留 ID，模板生成采用全新 ID 和未完成状态。日期保存为手机本地 `YYYY-MM-DD`，不用 UTC 换算；审计时间戳单独使用 UTC ISO 8601。周一为周首，增减日期按日历构造而非固定 24 小时，以避开夏令时跨日问题。

## 边界与隔离

模块使用 `[start, end)` 定位时间点，因此 12:00 属于下午、18:00 属于晚上。定时事项须满足 `module.start <= start < end <= module.end`。不同事项允许重叠；模块之间不得重叠。移动时读取目标日期快照或当前默认设置，时间不符则整笔事务回滚。

设置修改先校验所有模板定时事项并列出冲突；通过后只修改 defaults，完全不重写 `days.blocks`。模板复制会确认替换目标星期；应用后的日期和模板彼此独立。

## JSON 备份 v1

包含 `app`、`format_version`、`exported_at`、`settings`、`days`、`entries`、`templates`。先完整解析与校验类型、日期、唯一 ID、归属、时间范围、引用和快照；经用户确认后才事务清空并写入。失败保留旧数据。系统文件选择器完成读写，无外部存储权限。Debug/Profile 清单保留 Flutter 标准调试器所需的 INTERNET 权限，业务代码没有网络请求；Release 主清单没有联网权限。备份上限 10 MiB，每类记录上限 50000；日期选择范围 1900—2100 年。

## 范围

单机离线、人民币无关的日程产品；归属仅为本地标签。没有账号、同步、通知、自动转移未完成事项或无限重复引擎。演示数据入口未提供，新安装保持真实空白。系统云备份已关闭；用户可主动导出 JSON。
